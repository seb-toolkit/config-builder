When one student cannot use Safe Exam Browser: what the invigilator can do

Published 2026-11-26 · Unofficial guide

In every large SEB exam, one student's computer fails. You need a plan that is quick, fair and does not weaken the exam for everyone else. This guide gives the options in order of preference. The two Moodle routes in option 3 were tried on a test Moodle 4.5 site; see what was tested for the limits.

1. Try to fix it (a few minutes)

  • Check the usual causes: SEB opened on its own instead of from the quiz, another program running (screen sharing, a virtual machine), or an old SEB version. See what students are told to try.
  • Close SEB and launch again from Moodle. Moodle normally lets the student carry on with the same attempt.
  • Note the time and the exact message on screen.

2. Move them to another computer (the best fallback)

  • Use a spare lab computer or loan laptop that already has the right SEB and has been tried with this exam.
  • The student keeps the full SEB protection, and nothing about the exam changes.
  • Keep one or two spare machines ready. It solves most cases.

3. Run them without SEB, with you as the control

Use this only if someone can watch the student throughout, and only with your exam office's agreement. Two Moodle routes worked:

Route A: a duplicate quiz with SEB off, limited to one student

  1. Duplicate the quiz (or make a copy with the same questions) and set Require the use of Safe Exam Browser to No.
  2. Under Restrict access, add a Group restriction and use a group that contains only that student. Hide it from everyone else (the eye icon).
  3. Check by viewing the course as another student, or with a test account, that they cannot see it.

The real quiz is untouched. The cost is a second quiz with its own attempts and results to merge afterwards. A restriction by profile field (username) did not work in my test, whereas a group did, so use a group.

Route B: a bypass role for one student, on the same quiz

  1. As an administrator, create a role that is available at activity level and allow only the permission quizaccess/seb:bypassseb. Don't reuse the teacher role, which gives other powers.
  2. In the quiz, open Permissions and assign that role to the one student.
  3. Afterwards, remove the role from the student.

The student then opens the same quiz in an ordinary browser, while every other student is still held to SEB. By default only managers and editing teachers have that permission, which is why a teacher can open a quiz without SEB.

Add controls for the room

Without SEB nothing locks the computer, so you have to. Use several of:

  • the quiz password, which you give them in the room;
  • Require network address so the quiz opens only from the exam room;
  • a university computer where you can see the screen, with other programs closed;
  • a seat where you can watch, and a phone out of reach.

4. Other options

  • A paper or oral version, or deferring the sitting, if your regulations allow.
  • A different .seb file for that student, for example one that permits the Windows Hello sign-in programs. Moodle takes one settings file per quiz, so this also needs a duplicate quiz.

Whatever you choose

  • Write it down: the time, the student, the fault, what you changed and who agreed.
  • Settle the clock: how much time they lost and what they get back.
  • Be consistent: treat the next student with the same fault the same way.
  • Do not give the student the quit password or tell them to switch off settings.
  • Tidy up: hide or delete the duplicate quiz and remove the role afterwards.

What was tested, and what was not

On a local Moodle 4.5 site, with SEB set manually, I checked Moodle's access rule from the command line using a normal browser with no SEB headers:

CheckResult
Live quiz with SEB required, two studentsBoth blocked
Route A: duplicate quiz, SEB off, group of one studentThat student can see and open it; the other student cannot see it
Route B: bypass role assigned to one studentThat student allowed; the other still blocked

Not tested: an uploaded .seb file (the rule is the same code, but I did not use that path), a real attempt in a browser, how the role looks in Moodle's permission screens, and whether your university's rules allow manual invigilation. Try it on your own Moodle first.
