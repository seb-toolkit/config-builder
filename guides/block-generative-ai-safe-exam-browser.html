Preventing access to generative AI in Safe Exam Browser

Published 2026-11-26 · Unofficial guide

If your aim is to stop students using generative AI during an exam, the Safe Exam Browser (SEB) setting that matters is the website allow-list. Other settings, such as the address bar and back button, have little to do with it. This guide explains what works, what does not, and where SEB cannot help.

The setting that does the work: only list the sites students need

SEB's URL filter checks Block rules first, then Allow rules, and blocks any address that matches nothing. So when you allow only the exam site (and its sign-in), every AI assistant is blocked by default, including ones that do not exist yet. This is far more reliable than trying to list AI sites to block. See the URL filter guide for the pattern rules.

  • Stricter: check embedded content too. By default only the page a student navigates to is checked. Turn on "filter embedded content" and every request is checked, so an allowed page cannot load an AI chat widget or call an AI service from another site. The cost is that every site the quiz uses must be allowed, so test with a recorded run first.
  • If students must browse the open web, you cannot use an allow-list. The builder can allow everything and block a starting list of well-known assistants (for example chatgpt.com, openai.com, claude.ai, gemini.google.com, copilot.microsoft.com, perplexity.ai, poe.com, character.ai, deepseek.com, grok.com, meta.ai, chat.mistral.ai, you.com, phind.com and duck.ai). This is a deterrent, not a guarantee: new tools appear constantly, and search engines show AI-written answers on pages you cannot block without blocking search.

The address bar, back button and tabs

  • Address bar. On Windows, SEB shows a field for typing addresses only if you allow it, and the default is off. There is no separate read-only address bar: it is either a box students can type in, or nothing. Leave it off. Even if it were on, the allow-list would still block anything not listed. A separate setting controls whether SEB shows the page's address or its title in the window.
  • Back and forward. These only revisit pages the student has already opened, so with an allow-list they add no AI risk. The reason to leave them off for a quiz is different: going back inside an attempt can confuse the quiz. Switch them on when students browse web pages as part of the task.
  • Tabs. SEB has no tabs. Links that would open a new window are blocked, opened in the same window or opened in a new window, as you choose, and the filter applies to all of them.

What the filter does not cover

  • AI inside an allowed site. Moodle 4.5 includes AI features. In its source, the editor placement gives the student role permission to generate text and images by default, so if your Moodle has AI switched on, an answer editor may offer it. SEB cannot see that. Ask your administrator to turn the AI placements off, or remove the permission for students in exam courses, and check what an essay question's editor looks like to a student.
  • Other programs. SEB's own list of programs to block contains hundreds of entries, but only three are AI-related (AnyGPT, Cotypist and WunderType, in the version I checked). Do not rely on it. What protects you is SEB's kiosk mode, which hides other programs, and on managed computers, controls you set yourself.
  • Operating-system AI. SEB for Mac has settings for Siri and dictation, which the builder leaves off. I did not find a setting for other built-in AI features on Mac or Windows, and have not tested what Windows Copilot's keyboard shortcut does inside SEB, so check this on real computers.
  • Another device. A phone next to the computer is outside SEB's reach.

Recommended settings for a closed-book exam

  1. Allow only the exam site and its sign-in. No "any website".
  2. Consider checking embedded content as well, after a test run.
  3. Leave the address bar off. Leave back and forward off unless the task needs them.
  4. Ask your Moodle administrator about AI placements.
  5. Pair it with assessment design that is harder to answer with an AI, such as application to unseen data, or a short follow-up conversation, as discussed in the guide to secure exam environments.

Set it up in the builder

In the SEB Config Builder, choose "No: only the exam" or "Only a few sites that I will list" when it asks about browsing. The Fine-tune step then offers the stricter embedded-content check. If you choose "any website", it blocks the starting list of AI sites and warns you about the limits. Test the finished file in real SEB first.
