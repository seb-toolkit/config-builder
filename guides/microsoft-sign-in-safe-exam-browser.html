Microsoft sign-in, two-step verification and passkeys in Safe Exam Browser (2026)

Published 2026-11-26 · Unofficial guide

Many universities use Microsoft (Entra ID) to log students in to Moodle. When students sign in inside Safe Exam Browser (SEB), the type of second step matters a great deal. This guide summarises what is known as of November 2026 and what to do about it. It is based on public discussion in the SEB project, so treat it as guidance and test it on real computers.

The short version

  • Approval on a phone (the Authenticator app or a text message) is the safest option. The approval happens on the phone, outside SEB, so nothing special is needed in SEB itself, apart from allowing the Microsoft web addresses if you filter websites.
  • Windows Hello, a PIN, a passkey or a security key show a Windows security prompt. SEB can block or hide it, and the login page then waits forever.
  • Passkeys do not work in SEB for Mac or iPad, because the browser engine they use does not support them.

What the problem looks like

The SEB for Windows issue #1518 describes it. Microsoft is making passkeys the default sign-in method in Entra ID, and the issue gives September 2026 as the start. In SEB, the passkey prompt is a Windows Security (WebAuthn) window. An earlier report, #921, saw the same thing in 2024: the prompt opens in the background, or appears only after SEB is closed.

What helped people

  • Permit the Windows sign-in components. Add CredentialUIBroker.exe, PickerHost.exe and PinEnrollmentBroker.exe to SEB's permitted programs. The issue thread reports success with these three.
  • Choose the right Windows kiosk mode. With the default "separate desktop" mode, the prompt stays hidden. One user reported that the "disable Explorer shell" mode lets it appear.
  • Use a recent SEB. Some users on 3.10.1 had the problem fixed by upgrading to 3.10.2.
  • Avoid the passkey. One school switched accounts to Authenticator push approval and deleted synced passkeys.
  • Log in before SEB. A Moodle plugin avoids the sign-in inside SEB altogether: moodle-quizaccess_seb_autologin from ETH Zürich. A member of the SEB team suggested it in the issue thread, as a pilot that was "not yet thoroughly tested". Students log in as normal in their usual browser, start the quiz, and the plugin signs them in when SEB opens. Its page lists these requirements and limits: Moodle 4.2 or later over HTTPS, web services enabled, and the Safe Exam Browser access rule on the quiz. On Windows, startURLAppendQueryParameter must be true in the SEB settings. The token that carries the login lasts five minutes and is tied to the student's IP address. It does not apply to Moodle administrators, guests or suspended accounts. Its authors warn it may affect your setup, so test it on a copy of your site first, and ask your Moodle administrator, since it is a plugin that has to be installed.

The security trade-off

Permitting a program without checking its original name and its signature means a student could rename another program to match. The SEB maintainers raised this, and said a fix is planned for SEB 4, with no date given. The issue was closed by an automatic stale-bot on 24 November 2026 as "not planned", so do not assume a change is coming soon.

What the builder does

In the SEB Config Builder, the question "Do students sign in with a Microsoft account?" offers three answers:

  • No Microsoft sign-in.
  • Yes, approve on the phone. If you filter websites, the builder allows the Microsoft sign-in addresses (login.microsoftonline.com, login.microsoft.com, login.live.com, login.windows.net, msauth.net and msftauth.net). These come from Microsoft documentation, not from SEB, so confirm them with a recorded session as described in the URL filter guide.
  • Yes, Windows Hello, PIN, passkey or key. Windows only. It permits the three programs without a name or signature check, and switches the kiosk mode. The security warning above applies.

Recommended plan

  1. Ask students to use phone approval and to delete any passkey they have set up. Microsoft may offer a new passkey by default, so tell them to decline it.
  2. Test the whole sign-in on a real Windows computer, and on a Mac if you have Mac students.
  3. Have a fallback: a short practice quiz a few days before, so problems appear early.
