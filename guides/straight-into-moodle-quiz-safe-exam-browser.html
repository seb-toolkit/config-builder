Taking students straight into the Moodle quiz in Safe Exam Browser, with no site menus

Published 2026-11-26 · Unofficial guide

The aim: a student opens an SEB link, lands in the quiz, and has no way to wander off through the university or Moodle menus. This guide shows what Moodle really does at each step, from a test on Moodle 4.5, and how to close the gaps. Where I did not test something I say so.

What the student sees, step by step

  1. The launch link. Moodle's Launch Safe Exam Browser button is a link to the quiz's settings file with the address starting sebs:// (or seb:// for plain http). SEB opens, reads the file and goes to the quiz. Moodle replaces the start address in your file with the quiz's own, so you cannot send students anywhere else.
  2. Sign-in, if they are not signed in. SEB is a new browser session, so they usually meet the sign-in page first, then the quiz. See Microsoft sign-in and the autologin plugin in the downloads.
  3. The quiz page, with the Attempt quiz button.
  4. The attempt itself.
  5. The summary and review pages after finishing.

What I found on each page

I loaded each page in a local Moodle 4.5 as a student, with requests that Moodle accepts as coming from SEB, and counted the navigation.

PageLayoutSite menus
Quiz page (before the attempt)Ordinary course layoutFull menus shown: Dashboard, My courses, the course breadcrumb, messages, notifications and the user menu (profile, grades, preferences, log out). There were 19 different Moodle links.
During the attemptSecure layoutNone. Only the question navigation, Finish attempt and a way back to the quiz page.
Summary and review after the attemptSecure layoutNone. Moodle's SEB rule applies it to these pages.

So the risk is concentrated on the quiz page before the attempt starts (and again if the student goes back to it).

Why you cannot skip that page

An attempt starts only when the student presses Attempt quiz, which sends a request with their session key. I know of no Moodle setting that starts the attempt for them, and a link straight to the attempt page does not work. Plan for the quiz page rather than around it.

The fix: block the places the menus lead

You cannot hide the menu for SEB users alone with Moodle's own settings, but you can make every menu link lead nowhere using SEB's URL filter. Allow the Moodle host, then block these areas. The builder now adds all of them when you choose to keep students inside the quiz:

BlockWhy
/my/*Dashboard and My courses
/course/*The course page and breadcrumb
/calendar/*, /message/*Calendar, messages and notifications
/user/*Profile, preferences, private files, site support
/grade/*The grades overview in the user menu
/admin/*, /reportbuilder/*The data retention summary in the footer and custom reports
/badges/*, /blog/*, /search/*, /tag/*Other places the user menus and themes can link to
/login/logout.phpStops the student logging out mid-exam by accident
The site home page (a regular expression)The site name link; a simple rule cannot match the root address

I ran the 19 menu links from the quiz page through the builder's filter. Before this change, four were still open: the grades overview, the data-privacy page, the report builder and log out. After adding the rules above they are all blocked, while the quiz, attempt and Moodle's background requests (/mod/quiz/, /lib/ajax/) stay allowed.

What the student sees: the links are still on the page. Clicking one shows SEB's “blocked” message, and the student stays where they are. That is safe, but it can look like a fault, so tell students in advance.

Hiding the menus completely

I did not test this. A theme tweak could hide the navigation on quiz pages, but Moodle gives you no safe way to do it for SEB users only: a plain style rule would hide the menu for teachers too, and a custom plugin is more work than it is worth for most sites. The URL filter is the tested route.

Same window or a pop-up?

With Moodle's browser security left on None, Attempt quiz is an ordinary form: the page redirects to the attempt in the same window. I checked this on the test site and the quiz page had no links that open a new window.

It changes if the quiz's Browser security (under Extra restrictions) is set to Full screen pop-up with some JavaScript security. Then Moodle's start button opens the attempt in a pop-up window. It is a separate setting from the Safe Exam Browser one, and the SEB rule does not switch it off. What SEB does with that pop-up depends on its own new-window setting. My advice:

  • Leave Moodle's browser security on None for SEB quizzes. SEB already provides the locked-down screen.
  • In the .seb file, set links requesting a new window to open in the same window (or block them). SEB's own default is to open them in a new SEB window. The builder now sets this to the same window by default, and you can change it in the settings step.
  • Test any link in a question, a help icon or a university header link: each should stay in one window or be blocked.

I have not run the pop-up case in real SEB, so what it does there is untested.

What is still open

  • Links inside question text or feedback. Anything on an allowed site opens. Keep questions free of links, or use the website test to see what the quiz really requests.
  • Your university's own theme. A custom menu, footer links or a banner may add links that my plain test did not show. Check your own site, not mine.
  • Embedded content. Turn on the filter for embedded content if the exam must not load other sites inside a page.

How to check it on your own site

  1. Open the quiz page in SEB as a test student and click every menu link. Each should be blocked.
  2. Start the attempt and check there is no menu at all.
  3. Finish, look at the review page, then use the exit route you chose.
  4. Run a Moodle page through the builder's website test (a HAR file works) to see which addresses the page requests and whether any would be blocked by mistake.

What was tested, and what was not

A local Moodle 4.5 site with SEB set manually, requests sent with the right headers from the command line, and the builder's own filter engine for the link check. I did not use real SEB on Windows or Mac, an uploaded .seb file or a university theme, so confirm each with your own test run.
